# نشر Nexora PPE داخل الموقع

## قبل التشغيل

- شغّل التجربة داخل شبكة صناعية موثوقة، لا كخدمة عامة مكشوفة للإنترنت.
- وفّر `Model/ppe_unified_best.pt` المعتمد وثبّت بصمته. ملف الوزن قراءة فقط؛ `create_host_path: false` يمنع Compose من صنع مجلد يوحي بوجود وزن عند غيابه.
- تحتاج Docker Engine وCompose **2.33.1+** لدعم `gw_priority`، واتصالاً مصرحاً به لتنزيل صور/حزم البناء أو مرآة داخلية معتمدة.
- الشبكة الافتراضية للكاميرات تتيح اتصال RTSP الصادر؛ شبكتا proxy/API وAPI/database داخليتان. منفذ API وPostgreSQL غير منشورين على المضيف.
- حدّد VLAN الكاميرات، IP الموقع، DNS واسم المضيف والجدار الناري. مثال العناوين أدناه للتوضيح فقط.

## إنشاء الإعداد

من جذر المستودع، على جهاز إدارة موثوق:

```bash
python scripts/setup_onprem.py \
  --host nexora.site.lan \
  --rtsp-prefix rtsp://192.168.10.20:554 \
  --https-bind-address 192.168.20.10
```

السكريبت ينشئ `.env` بصلاحيات 0600 وأسراراً فريدة وكلمة مرور Admin مؤقتة ومفتاح تشفير نسخ. يرفض الكتابة فوق `.env` قائم. سلّم كلمة المرور عبر قناة خاصة، واحفظ مفتاح النسخ منفصلاً عن ملف النسخة.

لا تستخدم شبكات Docker الافتراضية إذا تعارضت مع شبكة الموقع؛ استخدم `--edge-subnet` و`--data-subnet` لنطاقين خاصين غير متداخلين. عناوين proxy المثبتة تحدد `TRUSTED_PROXIES` بدقة؛ لا تسمح بعناوين العميل أو الشبكة كلها كوكيل موثوق.

اضبط `PPE_MODEL_SHA256` في `.env` من سجل اعتماد الوزن، ثم:

```bash
docker compose config --quiet
docker compose build
docker compose run --rm --no-deps app python -m app.model_check --smoke
docker compose up -d
docker compose logs --tail=100 app
```

فحص الوزن لا يحتاج قاعدة البيانات. عند تشغيل API يبدأ فحص الوزن أولاً، ثم ترحيل قاعدة البيانات، ثم إنشاء حساب البداية ومدير الكاميرات. عند فشل أي بوابة يتوقف البدء؛ لا يوجد وضع استدلال بديل.

**حدود التحقق الحالي:** تم اختبار بنية YAML والإعداد المولّد وسياسات المسارات برمجياً؛ لم تتوفر Docker CLI أو خدمة PostgreSQL أو شبكة RTSP في بيئة التنفيذ. لم يُنفذ بناء/تشغيل Compose فعلي هنا، ويلزم تنفيذه في بيئة النشر قبل اعتماد التجربة.

## TLS والأسرار

Caddy يستخدم `tls internal` لشبكة الموقع. ثبّت شهادة جذر CA الصادرة من تثبيت Caddy في أجهزة المستخدمين عبر مسؤول الشبكة؛ لا تعطّل التحقق من الشهادة. احتفظ ببيانات Caddy في مجلداته الدائمة، أو راجع المؤسسة لتزويد شهادة معتمدة محلياً.

- لا تنشر 8000 أو 5432 خارج الشبكات المحددة.
- الواجهة وAPI والإطارات وWebSocket من الأصل نفسه. الإنتاج يتطلب HTTPS وأصول CORS وأسماء مضيفين دقيقة.
- Cookies الجلسات HttpOnly، ورموز الوسائط قصيرة العمر؛ logout وإعادة كلمة المرور وتعطيل الحساب تُبطل الجلسات.
- لا توجد أسرار في LocalStorage، ولا يُعرض عنوان RTSP الكامل في استجابات القوائم. قاعدة البيانات نفسها تحتوي بيانات اتصال الكاميرات؛ قيّد الوصول والنسخ.
- لا تسجل أسرار الكاميرات أو كلمات المرور أو رموز الجلسات في البلاغات. تجنب رفع صور العمال قبل حذف البيانات الحساسة والحصول على التصريح.
- تنبيهات SMTP/Webhook اختيارية؛ بياناتها أسرار خروج من الموقع ويجب السماح بها ومراجعة تسليمها صراحة.
- إعدادات الإنتاج ترفض الأسرار الضعيفة والأصول العامة. لا تُعد استخدام أسرار بيئة أخرى.

## إدارة الحسابات داخل Compose

نفّذ أوامر الحسابات داخل الحاوية التي تحمل إعداد PostgreSQL الفعلي، وليس من بيئة تطوير المضيف:

```bash
docker compose exec app python -m app.cli list-users
docker compose exec app python -m app.cli create-user --username recovery.admin --role admin
docker compose exec app python -m app.cli reset-password --username site.admin
```

هذه إجراءات إدارة محلية صريحة. تغيير بيانات حساب البداية في `.env` لا يعيد ضبط حساب قائم ولا ينشئ حساباً ثانياً تلقائياً.

## تشغيل مدير واحد

شغّل API بعامل Uvicorn واحد. مدير الكاميرات والكاشف والاشتراكات في ذاكرة العملية؛ استخدام عدة workers يكرر المصادر ولا يقدم توزيعاً متناسقاً. اختبر العدد المعتمد للكاميرات والحمل على جهاز الموقع قبل زيادة المصادر.

الانقطاع المستمر لا يُعد بثاً ناجحاً: `is_running` يحتاج إطاراً حديثاً. حدود OpenCV/FFMPEG للفتح والقراءة لا تغني عن اختبار المصدر الحقيقي. انتهاء فيديو يوقفه ولا يعيده تلقائياً عند إعادة تشغيل الخادم.

## النسخ الاحتياطي

مع خدمة PostgreSQL وتطبيق يعملان داخل Compose:

```bash
bash scripts/backup_postgres.sh
```

يُمرر pg_dump بصيغة custom إلى تشفير AES-256-GCM، ويحفظ ملف `.nxb` مشفراً بصلاحيات 0600. لا يكتب التفريغ غير المشفر على مضيف النشر. انقل النسخة إلى تخزين مستقل واحفظ `BACKUP_ENCRYPTION_KEY` في قناة منفصلة. لا يمكن استعادة نسخة دون مفتاحها الصحيح.

هذا السكريبت ينسخ **قاعدة البيانات فقط**. يلزم نسخ مجلدات الأدلة والفيديو وإعدادات التثبيت وشهادة الموقع والوزن المعتمد وسجل بصمته، بسياسة تشفير واحتفاظ موثقة. راجع الحصص والمساحة؛ الدليل الافتراضي يحتفظ بصور الإطارات 30 يوماً، لكن حذف صف SQL أو كاميرا ليس ضماناً لحذف ملف الدليل أو الفيديو.

## اختبار الاستعادة

اختبر أولاً في تثبيت منفصل، ولا تتدرب على قاعدة الإنتاج. امنع الدخول والكتابة وأوقف proxy والتطبيق قبل استعادة قاعدة فعلية. مثال، بعد وضع النسخة داخل مجلد النسخ الدائم:

```bash
docker compose stop proxy app
set -o pipefail
docker compose run --rm --no-deps -T app \
  python -m app.backup decrypt --input /var/nexora/backups/ARCHIVE.nxb --stdout \
  | docker compose exec -T db sh -c \
    'pg_restore --clean --if-exists --no-owner --no-acl -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

استبدل `ARCHIVE.nxb` باسم النسخة الفعلي. يتطلب فك النسخة مفتاحها الصحيح وصورة التطبيق وإعداداته المتوافقة. لا تستأنف التشغيل بعد أي فشل. افحص الجداول والملفات والإعدادات والصلاحيات في تثبيت الاستعادة، ثم أعد الخدمة فقط بعد التحقق.

الرجوع من ترحيل `20261024ind` يتطلب **نسخة ما قبل الترقية وصورة التطبيق السابقة والإعدادات والملفات المتوافقة معها**؛ تشغيل الصورة الجديدة على قاعدة قديمة يعيد تطبيق الترحيل. لا تستخدم downgrade لمحاولة إعادة بيانات محذوفة.

بعد الاستعادة، راجع سياسة إبطال الجلسات وتدوير الأسرار والحسابات النشطة حسب الحادث، واختبر الوصول والبث ودليل حدث وإعادة كلمة مرور دون الاعتماد على فحص liveness وحده.

## قبول التجربة الميدانية

يشترط قبول ملف الوزن وبصمته وفئاته، قياسات دقة للموقع، اختبار RTSP/HW والحمل، التحقق من PostgreSQL وTLS وفشل التنبيهات والمساحة، ونجاح استعادة كاملة. راجع [تقرير التحقق](VALIDATION_REPORT.md)؛ الاختبارات المعزولة ليست تصريح تشغيل نهائي.


## تحديث سياسة مصادر HTTP/USB

`ALLOWED_HTTP_CAMERA_PREFIXES` مستقلة ومغلقة افتراضيًا. يتطلب HLS السماح بكل الموارد الفعلية؛ يتحقق العميل من DNS ويثبت IP مع Host/SNI، يرفض التحويلات ووجهات metadata/link-local، ولا يرسل المصادقة إلى أصل مختلف. مفكك HLS يستقبل ملفات محلية مولدة فقط، مع بروتوكولات شبكة معطلة وحدود موارد وإيقاف عملية مستقل. لا يغني ذلك عن VLAN وجدار ناري يمنع الوصول إلى شبكات قواعد البيانات والخدمات الإدارية.

مولّد إعداد الإنتاج يبقي HTTP مغلقًا افتراضيًا إلا عند `--http-prefix` الصريح، ويدعم تثبيت HTTP-only دون قائمة RTSP صورية. يعطّل USB وloopback صراحةً. Compose الإنتاجي يثبت `ENABLE_USB_SOURCES=false` و`ALLOW_LOOPBACK_HTTP_SOURCES=false` ولا يمرر جهاز USB. أي تفعيل لهما خارج dev يُرفض من إعداد التطبيق.

حقول المصادقة للكتابة فقط، واستجابات الكاميرات منقحة ولا تعيد اسم المستخدم أو كلمة المرور أو المسار الأصلي. بيانات الاتصال الخاصة لا تزال محفوظة داخل قاعدة التثبيت الحالية؛ طبّق أقل صلاحية وتشفير وسيط التخزين وحماية النسخ الاحتياطية. لا تفعّل trace خامًا لمكتبات HTTP في الإنتاج؛ العميل يحجب URLs من سجل httpx ويوقف trace التفصيلي لـhttpcore. عنوان ONVIF بلا أسرار، وتسجيله لا يعني وجود discovery.

الترحيل `20261024src` إضافي غير حاذف ويحتفظ بالمصادر والأحداث، لكنه لا يجعل التطبيق الأقدم قادرًا على تشغيل الأنواع الجديدة. النسخ والاستعادة المختبرة مع إصدار متوافق تظل مسار الرجوع.
