# Mantik PPE · Industrial Safety Operations

منصة محلية لمراقبة معدات الوقاية في **المصانع، مواقع الإنشاء، الورش الصناعية، المستودعات والمناطق الصناعية فقط**. واجهة عربية RTL بهوية MANTIK ثابتة: Navy + Gold.

> **شرط التشغيل:** وفّر `Model/ppe.pt` المعتمد من مالك النموذج. هذا هو الاسم الوحيد المقبول: أي مسار أو اسم يحتوي `unified` أو `ppe_unified_best` يرفض الإقلاع برسالة `Only approved weight Model/ppe.pt is allowed; unified weights are rejected.` هذا الملف غير مرفق بالمستودع؛ غيابه يوقف تشغيل API والاستدلال بوضوح، دون تنزيل تلقائي أو وزن بديل. نجاح الاختبارات البرمجية لا يثبت دقة النموذج أو جاهزية موقع فعلي.

## الوظائف

- مصادر مميزة فعلية: RTSP/RTSPS وHTTP/MJPEG وHLS وملفات الفيديو، مع USB محلي للتطوير فقط. RTSP هو الخيار الموصى به للإنتاج.
- تحليل صور JPEG/PNG باستخدام نفس كاشف الكاميرات؛ معاينة معلّمة دون اختلاق تنبيهات زمنية من صورة واحدة.
- رفع فيديو MP4/AVI وتسجيله كمصدر متوقف، ثم معالجته **مرة واحدة بمعدل إطاراته الأصلي**. انتهاء الفيديو يوقف المصدر ويحرر موارده.
- قواعد خوذة الأمان، السترة العاكسة، قفازات العمل، حذاء الأمان والنظارات الواقية؛ تفعيل القواعد لكل مصدر.
- أحداث مخالفات مع صور دليل، معالجة الحدث، فلاتر موحدة للقائمة وتصدير CSV.
- إحصائيات SQL فعلية للموقع والفترة: إجماليات، أحداث مفتوحة/معالجة، سلسلة 24 ساعة أو 7 أيام. ليست عدّاً فريداً للعاملين أو نسبة التزام.
- إعداد المصانع والمواقع وربط الكاميرات بها، وحسابات Admin / Supervisor / Viewer.
- جلسات محلية، تغيير كلمة المرور المؤقتة، إبطال الجلسات، سجل تدقيق وتنبيهات اختيارية.

## عقد الاستدلال الواحد

| الإعداد | القيمة |
| --- | --- |
| اسم الوزن الوحيد | `ppe.pt` |
| المسار الافتراضي | `Model/ppe.pt` |
| ثقة العرض الافتراضية | `DETECTION_CONFIDENCE=0.50` |
| ثقة الدليل السالب المستقلة | `DETECTION_NEGATIVE_CONFIDENCE=0.60`؛ أقل قيمة مسموحة `0.60` |
| بصمة موصى بها | `PPE_MODEL_SHA256=15c758c669eeb557d9439bd18c5a3929680238122a95286210ca69e11af8218a` (تُتحقق عند ضبطها) |
| محمّل النموذج | `app/core/detector.py` |
| سياسة الملف | `app/core/model_policy.py` |
| مفردات الفئات والقواعد | `app/core/ppe.py` |

الفئات القياسية المقبولة:

```text
Person
Hardhat          / NO-Hardhat
Safety Vest      / NO-Safety Vest
Gloves           / NO-Gloves
Safety Boots     / NO-Safety Boots
Goggles          / NO-Goggles
Mask             / NO-Mask   (متجاهلة: غير صناعية)
```

فئات `ppe.pt` المتوقعة (13): Hardhat، NO-Hardhat، Safety Vest، NO-Safety Vest، Mask، NO-Mask، Person، Gloves، NO-Gloves، Safety Boots، NO-Safety Boots، Goggles، NO-Goggles. تُتجاهل `Mask`/`NO-Mask` في العرض والقواعد دون إسقاط التشغيل، ولا تُطلب فئات Ladder أو Cone أو Excavator.

تطبّع الأسماء المرادفة مثل `Boot` و`NO-Safety Boots` إلى الأسماء القياسية، دون افتراض أرقام الفئات. وفق تحديث توافق النموذج الموجود أصلًا على main، تُتجاهل أسماء الفئات غير الصناعية وتُحتفظ بأول هوية للفئة القياسية عند التكرار، ولا تُمرّر الفئات المتجاهلة إلى النتائج. الحد الأدنى الحالي هو Person وHardhat وNO-Hardhat وSafety Vest، ولا تُختلق فئة NO-Safety Vest إن غابت؛ **تحقّق من وجود زوج كل قاعدة إضافية قبل اعتماد استخدامها في الموقع**. وجود اسم ملف صحيح وحده لا يثبت مصدره؛ ثبّت SHA-256 من سجل اعتماد موثوق.

يُنشأ كاشف واحد مشترك آمن للخيوط عند بدء التطبيق؛ تستخدمه الكاميرات والصور والفيديو. لا توجد سلسلة محمّلات أو آلية استبدال. التنبيه يعتمد على تصنيف سالب صريح مستمر من النموذج، افتراضياً 8 ثوانٍ، مع مهلة تكرار 60 ثانية؛ لا يُستنتج نقص قطعة لمجرد عدم ظهورها.

## قرار PPE واحد قبل الرسم والتنبيه

كل مسارات الصور والفيديو والبث تستخدم `app/core/postprocess.py`: تُربط المعدات بكشف Person بأكبر IoU ثم أقرب مركز، وتُجمع الأدلة المتداخلة للشخص/القاعدة نفسيهما. يُختار أقوى موجب وأقوى سالب في المنطقة؛ الموجب يفوز بالتعادل أو الفرق أقل من `0.08`، وكذلك بمنطقة عدم اليقين حتى `0.15`. لا يفوز السالب إلا بتفوق **`0.15` على الأقل**. مثال الانحدار المثبت: Person + Hardhat `0.68` + NO-Hardhat `0.60` → **Hardhat فقط، دون مخالفة**.

- النتيجة المحسومة نفسها تسبق JSON والرسم والعدادات والثبات والتنبيه؛ لا يُرسم الصندوقان المتناقضان فوق المنطقة نفسها.
- تعرض الكشوف من `0.50` افتراضيًا. التنبيه يحتاج سالبًا صريحًا بحد `max(DETECTION_CONFIDENCE, DETECTION_NEGATIVE_CONFIDENCE)`، ثم الثبات والتبريد؛ تغيير حد السالب لا يخفض حد العرض. الصورة المفردة **معاينة فقط** حتى إن كان السالب قويًا.
- الذهبي للمعدات الموجبة، الرمادي الفاتح لـPerson، والأحمر للدليل السالب؛ اللون الأحمر وحده لا يعني إنشاء حدث زمني.
- `Boots`/`NO-Boots`/`NO-Safety Boots` تُطبّع إلى `Safety Boots`/`NO-Boot`. `Mask` و`NO-Mask` تُتجاهل في العرض والقواعد؛ ليست فئات منتج ولا سببًا منفردًا لفشل البدء.
- تكشف `/api/v1/meta/system` و`/api/v1/meta/ppe-classes` القدرات الفعلية للوزن بعد المصادقة. غياب `NO-Safety Vest` يعطل **إنذار السترة السالب فقط**؛ تظل السترة الموجبة قابلة للعرض، مع علامة «عرض فقط» في الاختيار. لا تُختلق فئة مفقودة.
- `person_index` ربط داخل الإطار لا هوية تتبع. إذا لم يُرصد Person فلا يُختلق؛ يُحسم التعارض المتداخل مكانيًا فقط. ثبات الإنذار الحالي لكل كاميرا/قاعدة، لا لكل عامل.

سياسة الوزن الكاملة في [docs/PPE_WEIGHT_POLICY.md](docs/PPE_WEIGHT_POLICY.md). التنفيذ ونتائج التحقق الحديثة في [تقرير Mantik](docs/MANTIK_PPE_UPDATE.md)، وكل مسار تغيّر وسببه في [سجل الملفات](docs/MANTIK_CHANGE_MANIFEST.md). تقارير الإصدار السابقة محفوظة كسجلات تاريخية ولا تمثل عدادات اختبارات هذا التحديث.

## تشغيل محلي مختصر

المتطلبات: Python 3.11+، Node.js 22.12+، وملف الوزن المعتمد. نفّذ الأوامر من جذر المستودع.

```bash
python -m venv .venv
source .venv/bin/activate                  # Windows: .venv\Scripts\Activate.ps1
python -m pip install -r requirements/dev.txt
cp .env.example .env                      # PowerShell: Copy-Item .env.example .env
python scripts/gen_jwt_secret.py
```

ضع السر الناتج في `JWT_SECRET`، وحدد `BOOTSTRAP_PASSWORD` قوية، وحدّث `ALLOWED_RTSP_PREFIXES` لشبكتك. انسخ الوزن المعتمد إلى المسار المذكور أعلاه، ثم:

```bash
python -m app.model_check --smoke
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

في نافذة ثانية:

```bash
cd frontend
npm ci
npm run dev -- --host 0.0.0.0 --port 5173
```

افتح `http://localhost:5173`. حساب البداية من `BOOTSTRAP_USERNAME`/`BOOTSTRAP_PASSWORD` ويُلزم بتغيير كلمة المرور. عند عدم ضبط بيانات تطوير دائمة تُولَّد بيانات عشوائية محلية وتظهر في سجل بدء التطوير؛ لا توجد كلمة مرور ثابتة. يُنشأ حساب البداية فقط إذا كان جدول المستخدمين فارغاً تماماً.

التطبيق يطبق Alembic قبل استقبال الطلبات. عند بناء `frontend/dist` يخدم FastAPI الواجهة من نفس الأصل على المنفذ 8000. استدعاءات المتصفح نسبية؛ وكيل Vite يمرر `/api` و`/frames` إلى API. `VITE_API_PROXY_TARGET` إعداد **خادم التطوير** فقط، وليس عنواناً يطلبه متصفح المستخدم.

## مصادر الكاميرات — الدعم الفعلي والحدود

| النوع في API | الاستخدام والحقول | التنفيذ والحدود |
| --- | --- | --- |
| `rtsp` | المصنع/الموقع؛ `rtsp://` ومنفذ اختياري ومصادقة إدخال فقط | **الافتراضي الموصى به للإنتاج**؛ مسار OpenCV/FFmpeg السابق محفوظ، وقائمة `ALLOWED_RTSP_PREFIXES` مطلوبة |
| `rtsps` | `rtsps://` فقط؛ منفذ الجهاز الفعلي | نفس مسار RTSP؛ يتطلب دعم الجهاز وبناء OpenCV/TLS، والتحقق الميداني ما زال مطلوبًا |
| `http_mjpeg` | HTTP(S) multipart MJPEG، ومنفذ وBasic/Digest اختياريان | قارئ HTTP مضبوط بمهل وحدود JPEG؛ لا يقبل HTML أو لقطة JPEG ثابتة |
| `hls` | HTTP(S) ومسار `.m3u8` | HLS عادي: TS/fMP4، قائمة رئيسية محدودة، حي/VOD، وAES-128 identity؛ فك FFmpeg عبر PyAV في عملية مستقلة **بلا بروتوكولات شبكة**؛ لا DRM أو LL-HLS أو مسارات صوت/فيديو منفصلة |
| `file` | `source_uri` لمسار MP4/AVI على **الخادم** | داخل `ALLOWED_VIDEO_DIR` فقط، معالجة مرة واحدة وبمعدل الملف الأصلي؛ رفع ملف المتصفح من صفحة التحليل |
| `usb` | `device_index` بلا URI | **dev محلي فقط، لا إنتاج ولا staging**؛ عملية OpenCV مستقلة قابلة للإنهاء عند تعليق السائق؛ يلزم تفعيل وفهرس مسموح |

النموذج يبدأ باختيار النوع ويعرض الحقول المناسبة. API يقبل `source_type` أو الاسم البديل `type`، ويمنع خلط البروتوكولات. حقول المصادقة `source_username` و`source_password` للكتابة فقط؛ لا تُرجع كلمات المرور أو الروابط الأصلية إلى الواجهة، ولا تُنسخ كلمة المرور القديمة عند استبدال الرابط. تغيير المصدر/المصادقة يوقفه حتى التشغيل مجددًا. تحفظ بيانات الاتصال الخاصة في قاعدة التثبيت الحالية؛ احمِ قاعدة البيانات ونسخها وصلاحيات نظام التشغيل، فهذا ليس ادعاءً بتشفير حقولها على القرص.

```dotenv
# RTSP أو RTSPS: اذكر كل بروتوكول/منفذ مطلوب صراحةً.
ALLOWED_RTSP_PREFIXES=rtsp://192.168.10.20:554,rtsps://192.168.10.21:322
# مغلقة افتراضيًا؛ أضف أصل/مسار الوسيط الحقيقي، لا وجهات عامة مفتوحة.
ALLOWED_HTTP_CAMERA_PREFIXES=http://192.168.10.30:8888/factory
ENABLE_USB_SOURCES=false
ALLOW_LOOPBACK_HTTP_SOURCES=false
```

كل طلب HTTP، بما فيه قوائم HLS والمقاطع والتهيئة والمفاتيح، يمر بفحص الوجهة وDNS وتثبيت عنوان الاتصال مع Host/SNI الأصليين. لا تُتبع التحويلات، ولا تُرسل المصادقة إلى أصل مختلف. تُرفض عناوين metadata وlink-local والعناوين المحلية المحظورة؛ loopback لا يُسمح إلا في dev مع مفتاح صريح **وقائمة سماح مطابقة**. تبقى سياسات الجدار الناري وعزل شبكة الكاميرات ضرورية.

المحاولات محدودة: 3 قراءات فاشلة ثم حتى محاولتَي إعادة فتح إجمالًا لكل تشغيل، بمهلة افتراضية ثانية بينهما. تعرض الواجهة «جارٍ الاتصال/إعادة اتصال/فشل الاتصال/اكتمل»، ولا تحتفظ بإطار أو عدادات قديمة على أنها بث حديث أثناء الانقطاع. الملفات لا تُعاد تلقائيًا. HLS محدود افتراضيًا إلى مخزن 128MB، وقائمة 256KB، و64 مقطعًا للقائمة و32MB للمورد؛ الإخراج حتى 5fps بإطار 960×540 مع حفظ النسبة وتوقيت الوسيط، لا سرعة فك VOD. هذه حدود نقل/فك وليست قياس FPS للاستدلال.

**ONVIF: تسجيل عنوان الجهاز فقط** في `onvif_device_uri`، ضمن قائمة HTTP وبلا مصادقة في الحقل. لا اكتشاف تلقائي ولا استخراج RTSP أو فيديو ONVIF. استخرج RTSP من إعدادات الجهاز أو أداة موثوقة ثم سجله كمصدر RTSP.

الكاميرات الاقتصادية قد تحتاج تفعيل RTSP في إعداداتها، أو قد توفر تطبيقًا سحابيًا فقط. إن توفر بروتوكول مدعوم، يمكن لوسيط محلي مثل **mediamtx** أو **FFmpeg** إعادة نشره داخل الشبكة؛ ليس هذا اكتشافًا تلقائيًا ولا ضمان توافق لكل كاميرا. مع mediamtx اختر HLS عاديًا (`hlsVariant: mpegts` أو `fmp4`) بدل LL-HLS، وأضف أصل ومسار الوسيط إلى قائمة السماح. راجع [خطوات الإعداد والقيود](docs/INDUSTRIAL_GUIDE_AR.md).

## الأدوار

| الصلاحية | Admin | Supervisor | Viewer |
| --- | :---: | :---: | :---: |
| عرض اللوحة والبث والأحداث والمواقع والتصدير | ✓ | ✓ | ✓ |
| إدارة وتشغيل المصادر، رفع ملفات، معالجة أحداث | ✓ | ✓ | — |
| تعديل المصانع والمواقع | ✓ | — | — |
| إصدار/تعطيل حسابات المشرف والمشاهد وإعادة كلمات المرور | ✓ | — | — |
| إصدار حساب Admin إضافي | CLI محلي فقط | — | — |

استعادة إدارية صريحة من جهاز موثوق، دون تغيير الأوزان أو تشغيل الاستدلال:

```bash
python -m app.cli create-user --username site.admin --role admin
python -m app.cli create-user --username shift.supervisor --role supervisor
python -m app.cli reset-password --username site.admin
python -m app.cli list-users
```

داخل Compose نفّذ هذه الأوامر عبر `docker compose exec app python -m app.cli ...` حتى تُطبَّق على قاعدة التثبيت لا قاعدة تطوير المضيف.

الكلمات المؤقتة تعرض مرة واحدة، ويجب تسليمها عبر قناة خاصة. لا يُسمح بتعطيل آخر Admin نشط.

## اختبارات التطوير

يمكن تشغيل الاختبارات المعزولة دون حزم ML أو أوزان:

```bash
python -m pip install -r requirements/test.txt
ruff check app migrations scripts tests
ruff format --check app migrations scripts tests
pytest -q --cov=app --cov-fail-under=75 --junitxml=test-results/backend.xml
cd frontend
npm ci
npm run lint
npm run format:check
npm test
npm run build
npx playwright install --with-deps chromium

```

اختبارات المتصفح تعمل على سطح المكتب والهاتف مع API مضبوط للاختبار فقط، وتفحص الإتاحة بـ axe. اختبار خط الفيديو يستخدم OpenCV وقاعدة SQL وصور أدلة حقيقية **وكاشفاً اصطناعياً صريحاً**؛ ليس اختبار دقة أو اعتماداً للوزن. يضيف `industrial-ci.yml` نفس بوابات الجودة إلى Pull Requests.

قبل ترقية أي بيانات موجودة: أوقف الكتابة وخذ نسخة كاملة قابلة للاستعادة. الترحيل `20261024ind` يزيل بيانات المصادر والأحداث غير المدعومة، يطبّع الأدوار، يوقف المصادر ويُبطل الجلسات، ويضيف المواقع ويحذف أعمدة النطاق السابقة. **الترحيل غير قابل للعكس؛ الرجوع باستعادة النسخة السابقة كاملة.** راجع ملفات الأدلة القديمة خارج قاعدة البيانات وفق سياسة الاحتفاظ، ولا تفترض أن حذف صف يحذف ملفه.

التحديث الإضافي `20261024src` يضيف حقول المصادر والمصادقة وعنوان ONVIF والخطأ الآمن، ويصحح نوع الصفوف القديمة ذات رابط RTSPS دون حذف مصادرها أو أحداثها. لا يعيد تنفيذ تنظيف `20261024ind`. لا يُنصح بالرجوع بكود أقدم إلى قاعدة تحتوي أنواعًا لا يفهمها؛ استعد نسخة متوافقة.

تشغيل تجريبي فعلي يتطلب الوزن المعتمد، فحص المصدر والبصمة والفئات، اختبارات صور/فيديو ممثلة للموقع وكاميرات RTSP حقيقية، معايرة الدقة والإنذارات والحمل، والتحقق من النشر والنسخ والاستعادة. هذه الخطوات ليست مستبدلة بنتائج CI.
